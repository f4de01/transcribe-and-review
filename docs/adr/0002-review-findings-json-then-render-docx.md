# 审查结果先落成 JSON，再由脚本确定性渲染 docx

审查报告的排版规则固定（问题片段连同时间戳标红、审查意见另起一行括号包含、风险提示红字、处理意见黄字），且要在 Claude、Codex 等不同宿主上产出一致的文件。我们让 agent 只输出一份结构化的审查结果 JSON（每条以起止段落时间戳定位，含风险类型、风险提示、法规依据、处理意见），由 Python 脚本（python-docx）把逐字稿与 JSON 合成为 docx；不让 agent 直接写 docx。直接写 docx 的做法依赖宿主的文档工具，各宿主结果不一致，排版样式也散落在 agent 的输出里无法统一修改。

## Consequences

- 改样式只改渲染脚本，不改 SKILL.md。
- JSON 中定位不到的时间戳由脚本报错而非静默跳过，agent 必须修正后重渲染。
- 审查结果 JSON 与 docx 同目录保留，可复核、可重渲染。
